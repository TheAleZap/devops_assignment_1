| 2026-09-29 / routers + static commit | Claude | Register scheduling and trips routers and serve the static frontend from the same process | Accepted | – | Scheduling and trips now have their own `APIRouter` (`scheduling_router` and `trips_router`), and both are connected to the main app using `app.include_router()`. The scheduling router uses the `/api/scheduling` prefix, so all scheduling endpoints are already grouped under the same URL structure. This will make it easier to separate Scheduling into its own service in Assignment 2. The frontend is served with `app.mount("/", StaticFiles(..., html=True))`, which makes FastAPI serve `index.html` together with the JavaScript and CSS files. Because this mount can match any path, it has to be registered last. FastAPI checks routes in the order they are added, so if the static mount came first, requests such as `/health` or `/api/*` would be treated as file requests and could return a 404. `STATIC_DIR` uses `os.path.dirname(__file__)` so the app can always find the `static` folder next to `app.py`, regardless of the folder from which the application is started. Finally, when the page loads, `app.js` sends a request to `/health`. If the API responds correctly, it reads the JSON response and displays `API status: ok` in the `#status` paragraph. If the request fails, it displays `API unreachable` instead. |
