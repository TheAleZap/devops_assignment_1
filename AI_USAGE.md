| 2026-10-01 / date-window algorithm commit | Claude | Design how to rank trip windows, then implement find_best_windows and the best-windows endpoint | Modified | I proposed ranking by convenience (weekdays cheaper and less crowded). We kept attendance as the main criterion because the app can't know a group's preference, and parked weekday preference as a possible poll setting for ADR-5. | find_best_windows turns each participant's free days into a set, then tries every start day from range_start up to last_start = range_end - (trip_length - 1), so no window runs past the range. Windows are sorted by the key (-len(available), missed_days, start): most people first (the minus sign makes the ascending sort put the highest count first), then fewest missed days, then earliest start, so the order is always the same and testable. sorted(free_days.items()) keeps names in alphabetical order. get_best_windows is a thin wrapper that loads the poll and passes its data to the pure function.
